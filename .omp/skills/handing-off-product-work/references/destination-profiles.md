# Destination Profiles

## OMP / repository mutator

Include exact repository/ref, file or subsystem scope, accepted requirement/work IDs, branch policy, test commands, candidate-retention rules, forbidden main/merge actions, and return receipts.

## GitHub issue

Title = one outcome. Body = context link, scope/non-scope, acceptance, dependencies, instrumentation, proof, owner. Do not paste the entire PRD.

## GitHub PR

Include why, source refs, changed behavior, requirement coverage, tests, screenshots/traces where relevant, risk/rollback, known gaps, and review focus. PR description never upgrades merge authority.

## Linear

Keep issue hierarchy shallow. Parent = outcome; children = independently verifiable slices/subtasks. Preserve source IDs and done criteria. Avoid one ticket per document heading.

## v0 / Lovable / Bolt / prototype builder

Compress to user, job, primary flow, screen/state inventory, interaction rules, content/data shape, visual constraints, non-goals, and prototype acceptance. Remove production infrastructure detail unless it changes the prototype.

## Research agent

Provide the decision question, allowed sources, freshness, evidence hierarchy, output schema, uncertainty labels, and prohibited actions. Research output remains evidence, not product authority.

## Human reviewer

Lead with decision requested, exact candidate, material changes, top risks, unresolved questions, and pass/fail gates. Do not bury the ask under provenance detail; link the ledger.
